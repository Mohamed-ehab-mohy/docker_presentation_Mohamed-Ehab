١Images — بناء وإدارة الـ Images

💡

الـ Image = القالب. الـ Container = نسخة شغّالة منه. بتبني الـ Image مرة واحدة وتشغّل منها كانتينرات قد ما تحب.

بناء Image من Dockerfile

بيقرأ الـ Dockerfile ويبني Image جديدة وسمّيها

BUILD 
docker build -t my-app:1.0 .

# مع Dockerfile في مكان تاني
docker build -t node-api -f docker-files/Dockerfile.node ./node-app
-t name:tagاسم الـ Image + الـ Tag (الإصدار). لو مكتبتش tag، هيبقى latest تلقائياً.
-f pathمسار الـ Dockerfile لو مش في المجلد الحالي.
. أو pathالـ Build Context — المجلد اللي الدوكر هيبعته للـ Dockerfile. النقطة = المجلد الحالي.
--no-cacheابنِ من أول وجديد بدون استخدام الـ Layer Cache. مفيد لما تحتاج Fresh Build.

عرض الـ Images الموجودة

شوف كل الـ Images المحلية — الاسم والحجم وتاريخ البناء

LIST 
docker images

# أو بالأمر الطويل
docker image ls

سحب Image من Docker Hub

نزّل Image جاهزة من الـ Registry بدون ما تبنيها

PULL 
docker pull nginx:latest
docker pull node:20-alpine
docker pull mcr.microsoft.com/mssql/server:2022-latest

حذف Image

امسح Image من جهازك لتوفير مساحة

DELETE 
docker rmi my-app:1.0

# لو الـ Image بيستخدمها كانتينر موقف، استخدم -f للإجبار
docker rmi -f my-app:1.0
-fForce — بيمسح حتى لو في كانتينر بيستخدم الـ Image دي.

معلومات تفصيلية عن Image

اعرف الـ Layers والـ Config والـ Env Variables الجوّانية

INSPECT 
docker inspect my-app:1.0

# استخرج معلومة معينة بـ format
docker inspect --format '{{.Config.Env}}' my-app

٢Containers — تشغيل وإدارة الكانتينرات

تشغيل كانتينر جديد

الأمر الأساسي — بيعمل كانتينر من Image ويشغّله

RUN 
# تشغيل في الخلفية (Detached)
docker run -d --name my-container my-app

# تشغيل تفاعلي (يفتح Terminal جوّاه)
docker run -it --name test ubuntu bash

# تشغيل واحذفه تلقائياً لما يخلص
docker run --rm my-app
-dDetached — شغّل في الخلفية ورجّع الـ Terminal ليك فوراً.
-itInteractive + TTY — افتح Terminal تفاعلي جوّا الكانتينر.
--nameاسم مخصوص للكانتينر بدل اسم عشوائي. بتستخدمه في كل الأوامر التانية.
--rmاحذف الكانتينر تلقائياً لما يوقف. مفيد للـ Testing.
--restartسياسة إعادة التشغيل: no | always | on-failure | unless-stopped

عرض الكانتينرات

شوف الشغّالة أو الكل بما فيهم الموقفة

LIST 
# الكانتينرات الشغّالة بس
docker ps

# الكل — شغّالة وموقفة
docker ps -a

# اعرض IDs بس (مفيد في Scripts)
docker ps -q
-aAll — بيعرض الكانتينرات الموقفة كمان.
-qQuiet — بيرجّع IDs بس. بتستخدمها في: docker stop $(docker ps -q)

إيقاف وحذف الكانتينرات

وقّف كانتينر شغّال أو احذفه نهائياً

STOP / RM 
# وقّف كانتينر بالاسم أو الـ ID
docker stop my-container

# احذف كانتينر موقف
docker rm my-container

# وقّف واحذف في خطوة واحدة
docker stop my-container && docker rm my-container

# وقّف كل الكانتينرات الشغّالة
docker stop $(docker ps -q)

# احذف كل الكانتينرات الموقفة
docker rm $(docker ps -aq)
-fForce — احذف الكانتينر حتى لو شغّال (من غير stop أولاً).

Start / Restart / Pause

إعادة تشغيل كانتينر موقف أو إيقاف مؤقت

CONTROL 
# شغّل كانتينر موقف (من غير ما تعمل run جديد)
docker start my-container

# إعادة تشغيل (stop ثم start)
docker restart my-container

# إيقاف مؤقت (freeze بدون حذف)
docker pause my-container
docker unpause my-container

٣Port Mapping — ربط البورتات

الكانتينر معزول تماماً — مفيش حاجة من بره توصّله. الـ -p HOST:CONTAINER بتعمل "ماسورة" من بورت جهازك لبورت جوّا الكانتينر.

ربط بورت واحد

وجّه ترافيك من جهازك لجوّا الكانتينر

PORT 
# بورت جهازك 5000 → بورت الكانتينر 3000
docker run -d -p 5000:3000 --name my-api node-api

# لو الـ App بتسمع على 80
docker run -d -p 8080:80 nginx

# اسمح من أي IP يوصّل (مش localhost بس)
docker run -d -p 0.0.0.0:5000:3000 node-api
-p H:CHOST:CONTAINER — رقم البورت على جهازك : رقم البورت جوّا الكانتينر.
-p H:C/udpلو محتاج UDP بدل TCP (الافتراضي).

بورتات متعددة

ربط أكتر من بورت لنفس الكانتينر

MULTI-PORT 
# HTTP + HTTPS مثلاً
docker run -d -p 80:80 -p 443:443 nginx

# API + Debug Port
docker run -d -p 5000:3000 -p 9229:9229 node-api

عرض البورتات الحالية

شوف البورتات المربوطة لكانتينر معين

INFO 
docker port my-container

٤Volumes — حفظ الداتا

⚠️

Containers are ephemeral — أي داتا بتكتبها جوّا الكانتينر بتتمسح لما تعمل له rm. الـ Volume بيحفظها برّه الكانتينر.

📦 Named Volume

الدوكر يدير التخزين. الأسهل والأنظف. مناسب للـ Databases والداتا المهمة.

📁 Bind Mount

بتربط مجلد من جهازك. بتغير الملفات وتشوف التغيير فوراً. مناسب للـ Development.

إنشاء واستخدام Named Volume

احفظ الداتا في Volume مستقل خارج الكانتينر

NAMED VOLUME 
# أنشئ volume
docker volume create my-data

# استخدمه في run
docker run -d -v my-data:/app/data --name my-app node-api

# بيشتغل مع SQL Server كمان
docker run -d -v sql-data:/var/opt/mssql mcr.microsoft.com/mssql/server
-v vol:/pathاسم الـ Volume : المسار جوّا الكانتينر. لو الـ Volume مش موجود، الدوكر هيعمله تلقائياً.

Bind Mount — ربط مجلد من جهازك

أي تغيير في المجلد يظهر فوراً جوّا الكانتينر

BIND MOUNT 
# Windows PowerShell
docker run -d -v C:\myapp:/app node-api

# Linux / Mac
docker run -d -v $(pwd)/src:/app/src node-api

# الصيغة الجديدة بـ --mount (أوضح)
docker run -d --mount type=bind,source=$(pwd),target=/app node-api

إدارة الـ Volumes

عرض وحذف الـ Volumes

MANAGE 
# اعرض كل الـ Volumes
docker volume ls

# معلومات تفصيلية عن Volume
docker volume inspect my-data

# احذف volume
docker volume rm my-data

# احذف كل الـ Volumes اللي محدش بيستخدمها
docker volume prune

٥Environment Variables — حقن الإعدادات

بدل ما تعمل Build جديدة لكل بيئة (Dev / Staging / Production)، حقن الإعدادات من بره. الـ Image واحدة والإعدادات بتتغير في الأمر.

حقن Variable واحد أو أكتر

مرّر إعدادات للكانتينر من Terminal مباشرة

-e FLAG 
# Variable واحد
docker run -d -e NODE_ENV=production node-api

# أكتر من واحد
docker run -d \
  -e NODE_ENV=production \
  -e PORT=3000 \
  -e DB_HOST=database \
  node-api

# SQL Server مثال
docker run -d \
  -e ACCEPT_EULA=Y \
  -e SA_PASSWORD=YourStr0ngP@ssword \
  mcr.microsoft.com/mssql/server
-e KEY=VALبيحدد Variable باسمه وقيمته.
-e KEYلو كتبت الاسم بس، بيورّث القيمة من بيئة Shell الخاص بك.

ملف .env — لما تكون الإعدادات كتير

خزّن الإعدادات في ملف ومرّره كله دفعة واحدة

ENV FILE 
# محتوى ملف .env
NODE_ENV=production
PORT=3000
DB_PASSWORD=secret123

# استخدام الملف
docker run -d --env-file .env node-api
--env-fileمسار ملف الـ env. مفيد جداً في الـ Production — خلّي الـ .env خارج الـ Git.

Variables في .NET — التحويل الخاص

.NET بيستخدم __ بدل : في أسماء الـ Settings على Linux

.NET SPECIAL 
# في appsettings.json بتكتب:
# ConnectionStrings:DefaultConnection

# في docker run بتكتب __ بدل :
docker run -d \
  -e ConnectionStrings__DefaultConnection="Server=db;..." \
  dotnet-api

٦Exec & Logs — دخول وتشخيص

الدخول لـ Shell جوّا الكانتينر

افتح Terminal تفاعلي جوّا الكانتينر الشغّال

EXEC 
# bash لو موجود
docker exec -it my-container bash

# sh لـ Alpine Linux (الأخف — بدون bash)
docker exec -it my-container sh

# تنفيذ أمر واحد بدون دخول
docker exec my-container ls /app
docker exec my-container cat /app/data/backup.txt
-itInteractive + TTY — لازم تحطهم لما تفتح Shell تفاعلي.
-e KEY=VALبتحقن Variable للأمر ده بس مش للكانتينر كله.
-w /pathWorking Directory — ابدأ الأمر من مجلد معين.

عرض الـ Logs

شوف الـ Output والأخطاء من الكانتينر

LOGS 
# كل الـ logs
docker logs my-container

# آخر 50 سطر
docker logs --tail 50 my-container

# متابعة live (زي tail -f)
docker logs -f my-container

# آخر 20 سطر + متابعة
docker logs --tail 20 -f my-container
-fFollow — متابعة الـ Logs في الـ Real-time. اخرج بـ Ctrl+C.
--tail Nاعرض آخر N سطر بس بدل كل التاريخ.
--sinceاعرض الـ Logs من وقت معين: --since 30m أو --since 2024-01-01

نسخ ملفات بين جهازك والكانتينر

انقل ملفات من/لجوّا الكانتينر الشغّال

COPY 
# من الكانتينر لجهازك
docker cp my-container:/app/logs/error.log ./error.log

# من جهازك للكانتينر
docker cp ./config.json my-container:/app/config.json

إحصائيات الأداء

شوف استهلاك CPU والـ RAM في Real-time

STATS 
# كل الكانتينرات الشغّالة
docker stats

# كانتينر واحد
docker stats my-container

# snapshot واحد بدون متابعة
docker stats --no-stream

٧Network — الشبكات

🌐

الكانتينرات على نفس الـ Network بتتكلم ببعض باسم الكانتينر مباشرة — مش محتاج IP. Docker Compose بيعمل الـ Network ده تلقائياً.

إنشاء واستخدام Network

اعمل شبكة خاصة لكانتينراتك يتكلموا فيها

NETWORK 
# إنشاء network
docker network create my-network

# شغّل كانتينرات على نفس الشبكة
docker run -d --network my-network --name database mcr.microsoft.com/mssql/server
docker run -d --network my-network --name api node-api

# دلوقتي الـ api يقدر يتكلم الـ database باسمه
# Server=database (مش Server=localhost!)

إدارة الـ Networks

عرض وحذف الشبكات

MANAGE 
# اعرض كل الشبكات
docker network ls

# تفاصيل شبكة — مين فيها
docker network inspect my-network

# احذف شبكة
docker network rm my-network

# وصّل كانتينر شغّال لشبكة
docker network connect my-network my-container

# افصل كانتينر من شبكة
docker network disconnect my-network my-container

٨Docker Compose — أوامر أساسية

بدل ما تشغّل كل كانتينر بيده، docker compose بيشغّل كل حاجة بأمر واحد من ملف YAML واحد. الشبكة والـ Volumes بتتعمل تلقائياً.

تشغيل وإيقاف السيستم

الأوامر الأساسية اليومية في docker compose

UP / DOWN 
# شغّل كل الـ Services (واقف — بتشوف الـ Logs)
docker compose up

# شغّل في الخلفية
docker compose up -d

# شغّل + ابنِ الـ Images أولاً
docker compose up --build

# شغّل في الخلفية + Build
docker compose up --build -d

# وقّف كل حاجة + امسح الكانتينرات والشبكات
docker compose down

# وقّف + امسح الـ Volumes كمان
docker compose down -v
--buildأعد بناء الـ Images قبل التشغيل. حطها لما تعدّل الكود.
-dDetached — شغّل في الخلفية.
-vفي down — بيمسح الـ Volumes كمان. احذر مع الداتا المهمة.

ملف compose مختلف

لما عندك ملفات compose متعددة

-f FLAG 
docker compose -f docker-files/docker-compose.yml up --build
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-files/docker-compose.yml down

Logs ومراقبة الـ Services

تابع ما بيحصل في كل Service

LOGS 
# logs كل الـ Services
docker compose logs

# Service معين + متابعة
docker compose logs -f node-app

# آخر 50 سطر
docker compose logs --tail 50 node-app

أوامر إضافية مفيدة

للـ Debugging وإدارة الـ Services

EXTRA 
# اعرض الـ Services وحالتها
docker compose ps

# أعد تشغيل Service واحدة
docker compose restart node-app

# ابنِ الـ Images بدون تشغيل
docker compose build

# نفّذ أمر في Service شغّالة
docker compose exec node-app sh

# شغّل Service مرة واحدة بس (مش تفتحها دايم)
docker compose run --rm node-app npm test

٩Cleanup — التنظيف واسترداد المساحة

💡

Docker بيراكم Layers قديمة وكانتينرات موقفة وـ Volumes يتيمة. نظّفها بانتظام.

تنظيف شامل

امسح كل حاجة مش بتستخدمها دلوقتي

PRUNE 
# امسح الكانتينرات الموقفة + الشبكات غير المستخدمة + الـ Images اليتيمة
docker system prune

# نفس الكلام + الـ Volumes
docker system prune --volumes

# نفس الكلام + الـ Images اللي محدش بيستخدمها (حتى لو مش يتيمة)
docker system prune -a

# الـ Nuclear Option — امسح كل حاجة بدون سؤال
docker system prune -a --volumes -f
-aAll — بيمسح كل الـ Images المش مستخدمة، مش بس اليتيمة.
--volumesبيمسح الـ Volumes اللي محدش بيستخدمها. ⚠️ احذر من داتا مهمة.
-fForce — بيمسح بدون سؤال "أنت متأكد؟"

تنظيف موجّه

نظّف نوع محدد فقط

TARGETED 
# امسح بس الكانتينرات الموقفة
docker container prune

# امسح بس الـ Images اليتيمة (dangling)
docker image prune

# امسح بس الـ Volumes غير المستخدمة
docker volume prune

# امسح بس الشبكات غير المستخدمة
docker network prune

معرفة المساحة المستخدمة

شوف بالتفصيل بيستخدم إيه قد إيه

DISK USAGE 
docker system df

# تفصيلي أكتر
docker system df -v
